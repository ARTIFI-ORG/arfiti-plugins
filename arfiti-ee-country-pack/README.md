# Arfiti Estonia Country Pack

Everything an Estonian company (OÜ or AS) needs on top of the Arfiti ERP, in one plugin: the monthly VAT return (KMD) with its annex and the EC Sales List, gross-to-net payroll with the TSD declaration, the annual report with its XBRL file for the e-Business Register, and a guided build of a full year's books. Four skills, loaded only when the task matches; files for the tax authority and the register are generated by deterministic scripts, and you upload them yourself.

## Requirements

- An Arfiti organisation with a legal entity in Estonia, and a user who can sign in to it.
- The **Arfiti** connector (`https://mcp.arfiti.com/streamable/mcp`). This plugin's `.mcp.json` points at the same server, so installing both shows one set of tools.

## VAT return (KMD) and EC Sales List

Prepares the monthly Estonian VAT return (KMD) for e-MTA from your Arfiti ledger. It discovers and classifies tax codes instead of assuming them, runs a pre-close validation gate that blocks or warns, then generates the KMD2 machine CSV and an XSD-validated XML with the KMD INF annexes. The EC Sales List (Form VD) is prepared separately as a data table for portal entry. The tax period is locked after filing.

| Command | What it does |
| --- | --- |
| `/prepare-vat-declaration` | Run the validation gate, then generate the KMD2 CSV and XML with the KMD INF annex. Add `validate` to run the gate only. |
| `/prepare-ec-sales-list` | Prepare the EC Sales List (Form VD) for intra-EU B2B supplies as a KMD-reconciled table for portal entry. |

## Payroll and the TSD declaration

Estonian payroll for Arfiti legal entities: gross-to-net calculation with income tax, social tax, unemployment insurance, funded pension and voluntary deductions, submitted to the ERP, and generation of the monthly TSD declaration XML for e-MTA from an approved payroll run. The XML is produced by a deterministic script against the official e-MTA schema, and you upload it yourself.

| Command | What it does |
| --- | --- |
| `/calculate-payroll` | Calculate gross-to-net payroll for an Estonian legal entity and submit the results to the ERP. |
| `/generate-tsd` | Generate the e-MTA TSD XML from a calculated or approved payroll run, ready for upload to maasikas.emta.ee. |

## Annual report and XBRL

Prepares the Estonian annual report (majandusaasta aruanne) for the e-Business Register. It guides step by step through the balance sheet, income statement, notes and management report from your Arfiti ledger, then generates the XBRL instance and companion schema files using the et-gaap 2026 taxonomy. You upload the files to ariregister.rik.ee yourself.

| Command | What it does |
| --- | --- |
| `/prepare-annual-report` | Prepare the full annual report for a legal entity. |
| `/check-prerequisites` | Check whether the legal entity is ready for annual report preparation. |
| `/generate-xbrl-mapping` | Generate the account-to-XBRL element mapping table for portal data entry. |
| `/generate-xbrl-file` | Generate the `.xbrl` and `.xsd` files for upload to ariregister.rik.ee. |

## Year-end bookkeeping

Full year-end bookkeeping for Estonian companies (OÜ and AS) in Arfiti, for business owners, freelancers and accountants. It builds a complete year of accounts from scratch in five phases: entity and chart of accounts setup, opening balances, bank statement processing month by month, gap filling with source documents and year-end adjustments, and reconciliation with period close. It prepares the entity for annual report filing.

| Command | What it does |
| --- | --- |
| `/setup-entity` | Phase 1: import the chart of accounts, create bank accounts and configure posting profiles. |
| `/upload-opening-balance` | Phase 2: import and verify opening balances from the prior year (skip for first-year companies). |
| `/process-bank-statements` | Phase 3: read bank statements, create vendors and customers, classify and post transactions, month by month. |
| `/fill-gaps` | Phase 4: find missing bills and invoices and post source documents and year-end adjustments. |
| `/reconcile-and-close` | Phase 5: verify the trial balance and balance sheet, reconcile bank accounts, close fiscal periods and hand off to the annual report skill. |
| `/check-progress` | Show progress across all five phases, what is next and any issues. |

## What it runs and sends

The plugin contains skills, commands and helper scripts under `scripts/`. The scripts use only the Python standard library and open no network connection. Data is read from and submitted to your Arfiti organisation through the connector; anything you upload to a government portal you upload yourself. The plugin sends data only to the Arfiti MCP server over the authenticated connector and runs no code of its own that contacts any other service. The only files the scripts write are the outputs named below.

### VAT return (KMD) and EC Sales List

`generate_kmd.py` (Python 3, standard library only) reads the JSON file you pass with `--input` and writes two files to the folder you pass with `--output` (default: the current folder): `KMD_<yyyymm>_<regcode>.csv` and `vatDeclaration_<yyyymm>_<regcode>.xml`. Before writing the XML it validates it against the bundled `vatdeclaration.xsd` by running the local `xmllint` program (libxml2) on a temporary file, which it deletes afterwards; if `xmllint` is not installed it prints a warning and skips validation. `input_schema_kmd.json` describes the input and is not executed. With `--select-inf <invoices.json> --side A|B` it instead reads an invoice list and prints which partners the KMD INF annex must list (invoices without VAT at least EUR 1,000.00 per partner, per EMTA's KMD INF instructions), which are below the threshold or excluded, and which still need a verified register code; it writes no files. It refuses the cash-accounting-only annex columns (`invoiceSumForRate`, `vatSum`) unless the input sets `cash_accounting: true`, and a partner code shaped like a VAT number. The ledger data is read from your Arfiti organisation through the connector, and locking the tax period after filing is a write you confirm through the connector.

### Payroll and the TSD declaration

- `generate_tsd.py` reads the JSON file you pass with `--input`, validates it, and writes one file, `TSD_<year><month>_<regcode>.xml`, to the folder you pass with `--output` (default: the current folder). It prints a tax summary to the terminal.
- `input_schema_tsd.json` describes the input and is not executed.

### Annual report and XBRL

`generate_xbrl.py` (Python 3, standard library only) reads the JSON file you pass with `--input`, checks the balance sheet and cash flow, and writes two files to the folder you pass with `--output`: `Vormid_<regcode>.xsd` and `Aruanne_<regcode>.xbrl`. It builds them entirely from the input and hardcoded namespaces; the taxonomy URLs in the output are identifiers written into the files and are never downloaded. `input_schema.json` describes the input and is not executed. The report data itself is read from your Arfiti organisation through the connector.

### Year-end bookkeeping

No scripts, hooks or local servers. Postings and period closes are submitted to your Arfiti organisation only through the connector's tools, under its authorization, approval and audit controls.
